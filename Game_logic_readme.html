RobuLingo – Game Logic (Item Presentation)

Scope: how items are selected, repeated, and switched between comprehension (2AFC) and naming (speech/ASR), including postponing/reactivating naming blocks and re-insertion via a FIFO refiller queue.

Intent

  • Learning Teach vocabulary by alternating recognition (2AFC) and production (naming).
  • Control Use a predictable schedule (fixed block size, explicit promotion/removal rules, FIFO refill).
  • Resilience Prefer local persistence (logs + refiller) and prefetch neighborhoods to reduce stalls.

Source of truth (code)

  • Policy / scheduler: lib/logic/item_presentation_policy.dart
  • Session orchestration + UI wiring: lib/app/robulingo_app.dart
  • Refiller persistence: lib/logic/refiller_store.dart
  • Logs: lib/event_logger.dart writes events.ndjson
  • Curriculum + assets: lib/data/api_client.dart

Core concepts

  • CurriculumEntry = curriculum slot (uuid + index).
  • ItemData = resolved item (L2 text, optional L1/native text, optional phonetic, image/audio).
  • PresentationSlot = (mode, targetUuid) from the policy.
  • Trial = 2AFC “render object” built on-demand for the current slot (target vs distractor).
  • readyToName = UUIDs that qualified for naming (rolling 5/5 comprehension).
  • trialIndex (current meaning) = slot position in the 10-item comprehension cycle (0..9), or -1 while naming.

Item presentation policy (current rules)

  1. Comprehension block of 10: slots 1..9 are serial curriculum items; slot 10 is filled from refiller FIFO (fallback to curriculum if empty). The block wraps after slot 10 back to slot 1.
  2. Distractors: chosen randomly from the previous 10 curriculum items; if there are fewer than 10 previous items, chosen from the next 10. Neighborhoods are prefetched.
  3. Up-from-comprehension: when an item reaches 5/5 correct in a rolling window (answered attempts only), it qualifies for naming and is removed from the comprehension block.
  4. Down-from-comprehension: if an item is answered in comprehension more than 20 times, it is removed from the comprehension block and enqueued into refiller.
  5. Naming blocks (Option A): naming preempts comprehension when a naming block is available (block size = 5 items).
  6. Postpone naming: in naming view, a toggle (assets/icons/postpone.webp) postpones the current naming block. Remaining items are enqueued FIFO as a postponed block. Only the last 3 postponed blocks are kept.
  7. Reactivate naming: in comprehension view, when postponed blocks exist, a toggle (assets/icons/antepone.webp) reactivates postponed blocks FIFO.
  8. Up/down-from-naming: if naming correct > 2 (mastery) or naming attempts > 8 (down-from-naming), the item is removed from naming and enqueued into refiller (so it can reappear later for forgetting/re-exposure).
  9. Naming mic recovery: after gate-allow, if mic prime is not ready, naming stays on hold (no automatic fallback for this case). The UI shows explicit actions: retry mic, open settings, or continue without mic. On app resume, mic readiness is re-checked and no-mic mode is cleared automatically when permissions are restored.

Cursor and persistence

  • Log-derived cursor (primary): scanning backward in events.ndjson for the last matching trial_result of the active start_key and lang (and user if available).
  • Delta cursor (fallback): UserCurriculumDelta.cursor is persisted as a safety net if logs are missing/ambiguous.
  • Refiller FIFO: stored locally via RefillerStore (one JSON file per user+curriculum+lang in the app documents directory).

Display rules (L1 + phonetics)

  • L1/native text: shown on the 1st and 3rd presentation of an item (0-based exposure count: 0 and 2) when L1 is enabled.
  • Phonetics: shown for the first 4 presentations (plus an optional per-item “show again” override).

What you can modulate (training parameters)

Most knobs are code-level today. Primary knobs live in ItemPresentationConfig.

ParameterWhereEffect
comprehensionBlockSize (10), comprehensionCoreSize (9) lib/logic/item_presentation_policy.dart Size/shape of the repeating comprehension block; last slot is refiller-driven.
distractorWindow (10) lib/logic/item_presentation_policy.dart Neighborhood size for distractor sampling and prefetch.
compWindowSize (5), compWindowCorrectNeeded (5) lib/logic/item_presentation_policy.dart How strict naming qualification is (rolling window and required correct answers).
minQualifiedItemsToStart (5), namingBlockSize (5) lib/logic/item_presentation_policy.dart When naming begins and how many items each naming block contains.
comprehensionDownMaxAttempts (20) lib/logic/item_presentation_policy.dart Down-from-comprehension removal threshold (answered attempts only).
namingMasteryCorrectThreshold (2), namingDownFromNamingMaxAttempts (8) lib/logic/item_presentation_policy.dart When items leave naming and go back to refiller for later re-exposure.
maxPostponedBlocks (3) lib/logic/item_presentation_policy.dart How many postponed naming blocks are retained (FIFO; older dropped).
L1 schedule (_shouldShowNative) lib/app/robulingo_app.dart Which exposures show L1/native text (currently counts 0 and 2).
Phonetic schedule lib/app/robulingo_app.dart Which languages show phonetics and for how long (first 4 exposures + override).
Naming mic recovery behavior lib/app/robulingo_app.dart Gate allow + prime failure now keeps naming on hold with explicit user actions (retry/settings/without-mic) and an automatic re-check on app resume.
