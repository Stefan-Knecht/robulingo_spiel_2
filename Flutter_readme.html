RobuLingo - Flutter App

This Flutter client loads curricula and item assets from the RobuLingo Worker/R2 buckets, builds 2AFC trials, and logs session activity for review.

Runtime workflow (step-by-step)

  1. Start the app via lib/main.dart, which mounts RobuLingoApp.
  2. Select the target language and a start curriculum file.
  3. ApiClient loads curricula and item assets (JSON, images, audio) from the Worker/R2.
  4. TrialBuffer builds the trial queue, inserts review trials, and keeps a window of items.
  5. The session UI renders 2AFC choices, handles audio playback, and updates progress tracks.
  6. If enabled, the naming gate uses speech recognition to capture spoken answers.
  7. EventLogger writes NDJSON locally and uploads batches via LogUploader.
  8. User curriculum deltas are fetched and pushed through UserCurriculumService.

Eingebaute Logiken (einfach erklaert)

  • Session-Logging: Jede Aktion schreibt eine JSON-Zeile in logs/events.ndjson (lokal). Uploads sind optional und passieren spaeter.
  • Session-Gruppierung: Events werden per Session-ID gebuendelt; die gesamte Session zaehlt fuer den Tag, an dem sie gestartet wurde.
  • Aktive Zeit: Zeitabstaende zwischen Events werden summiert, aber lange Pausen werden auf idleCapSeconds gedeckelt.
  • Qualifizierte Tage: Ein Tag gilt als "geschafft", wenn die aktive Zeit den Schwellwert thresholdMinutes erreicht.
  • Rival-Markierungen: Der Rival-Kreis erscheint auf jedem Trainingstag (gemeinsam) und zusaetzlich einmal pro Woche auf einem Rival-only-Tag, wenn im 14-Tage-Fenster weniger als 9 Tage qualifiziert sind.
  • Kalender-Refresh: Die Ansicht laedt die Logs in festen Intervallen neu, damit neue Eintraege sichtbar sind.

App presentation order

The in-app order is driven by the curriculum, with periodic review trials to keep previously seen items active.

  1. Curriculum entries are sorted by position, falling back to original index if missing.
  2. Items load in batches and each item becomes a target for a 2AFC trial.
  3. Distractors are selected from nearby items (next 5, then previous 5, then expand outward), skipping identical UUIDs or image signatures.
  4. Image variants are selected randomly per trial and the target side is randomized.
  5. Every reviewInterval trials, a review trial is injected from previously presented items.

Key modules

  • lib/main.dart: App entry point and theme setup.
  • lib/app/robulingo_app.dart: Core session state, loading, and orchestration.
  • lib/data/api_client.dart: Curriculum and item loading from Worker/R2.
  • lib/data/user_curriculum_service.dart: Fetch/push per-user curriculum deltas.
  • lib/logic/trial_buffer.dart: Trial queue with distractor selection and review injection.
  • lib/logic/naming_controller.dart: Speech recognition and naming flow.
  • lib/event_logger.dart: Local NDJSON logging and upload scheduling.
  • lib/ui/session/session_widgets.dart: Session UI and trial rendering.
  • lib/constants.dart: Hosts, bucket URLs, review intervals, and language list.

Run and build

  • flutter pub get
  • flutter run -d macos (or choose another target device)
  • Update lib/constants.dart if Worker hosts or bucket URLs change.

Assets and configuration

  • assets/: Local images and sounds referenced in pubspec.yaml.
  • pubspec.yaml: Dependencies, assets, and Flutter config.
